# Архитектура

Статический сайт без фреймворков. Сервера нет: данные — JSON-файлы, состояние пользователя — `localStorage`
(префикс `yulia.v2.`).

## Карта модулей

| Модуль | Роль |
|---|---|
| `js/boot.js` | **классический** скрипт в `<head>`: тема до первой отрисовки, заставка («Далее», выбор темы), переключатель темы, сторожевой таймер с баннером «приложение не стартовало» |
| `js/app.js` | точка входа ES-модулей; ставит `window.__yuliaModuleOk`, грузит данные, запускает разделы |
| `js/data-loader.js` | `loadAll()` читает `data/*.json` (или `window.__YULIA_DATA__`), кэш в localStorage как запасной вариант; `buildCalcConfig()` собирает единый конфиг формул |
| `js/state.js` | общее состояние: `DATA`, `CFG` |
| `js/router.js`, `js/theme.js` | навигация по секциям; реакция карты и графиков на тему (событие `yulia:theme`) |
| `js/overview.js`, `calc-panel.js`, `market.js`, `map.js`, `guide.js`, `checklist.js` | разделы |
| `js/calculators/*.js` | чистые функции расчёта, без DOM; тесты в `tests/` |
| `js/ui/` | помощники (`helpers.js`), отрисовка полей и результатов калькуляторов |
| `js/charts.js` | фабрика графиков Chart.js |

## Поток данных

```
data/*.json ──loadAll()──▶ state.DATA ──buildCalcConfig()──▶ state.CFG ──▶ разделы (init*)
                │                                                  ▲
   window.__YULIA_DATA__ (офлайн)                       ручные правки из localStorage (applyOverrides)
```

Каждый раздел запускается в `safe()`: ошибка пишется в консоль и в плашку, остальные разделы работают.
Нет данных: раздел показывает «нет данных» и ручной ввод, ничего не придумывая.

## boot.js против модулей

Модули не работают по `file://` и при сбое загрузки. Всё, без чего страница выглядит сломанной
(тема, заставка, «Далее»), живёт в классическом `boot.js` и от модулей не зависит. Не переписывайте его в модуль.

## Сборка (`scripts/build.mjs`)

- **Сайт** (`_site/index.html`): `js/app.js` → `assets/app.js` (esbuild, IIFE, ES2019); тег
  `<script type="module">` заменён на `<script defer src="assets/app.js">`. `defer` сохраняет порядок:
  CDN-библиотеки выполняются раньше приложения.
- **Офлайн** (`_site/yulia-offline.html`): стили в `<style>`, `boot.js` и бандл в классических `<script>`,
  данные: `window.__YULIA_DATA__ = {…}` перед бандлом (ключи — имена файлов без `.json` и `archive_html`).
  Бандл стартует по `DOMContentLoaded`, чтобы CDN-скрипты уже были выполнены. `</script` и `<!--` экранируются.
- Нет esbuild: запасной путь, копия исходных модулей.

## Правила данных (провенанс)

1. Любая цифра, ставка, порог, дата — только из `data/*.json`; констант в расчётных модулях нет.
2. Поля значения: `value`, `unit`, `source_name`, `source_url`, `fetched_at`, `valid_from`, `confidence`.
3. Нет данных: `value: null`, `status: "no_data"`; ручной ввод в интерфейсе. Предположения проекта — `confidence: "model"`.
4. Сбой автообновления: значение остаётся, ставятся `stale: true`, `stale_since` (`scripts/fetch-util.mjs`).
5. Внешние запросы скриптов: таймаут 10 с, ретраи 500 мс × 2ⁿ с джиттером, 4xx не повторяются.

## Соглашения

- Комментарии в коде — по-русски, к логическим блокам; заглушек нет.
- Дизайн: монохромные токены из `css/tokens.css` / `themes.css`, цвета не хардкодятся.
- Анимации: только `transform` и `opacity`, кривая `cubic-bezier(0.16,1,0.3,1)`, `prefers-reduced-motion` уважается.
- Библиотеки с закреплёнными версиями (CDN в `index.html`, `esbuild` в `package.json`), секретов в коде нет.
- `package.json` с `"type": "module"`: `.js` и `.mjs` — ES-модули.
