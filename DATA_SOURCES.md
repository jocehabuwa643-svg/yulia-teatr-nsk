# DATA_SOURCES.md — источники данных, статусы, как обновлять

Правило проекта: **ни одной цифры без источника, даты проверки и confidence.** Значение с
`status:"no_data"` показывается в интерфейсе как «нет данных» + форма ручного ввода; график не
подделывается никогда. Провенанс лежит рядом с каждым значением в `data/*.json`
(`value, unit, label, source_name, source_url, fetched_at, valid_from, valid_to, confidence, note, legal_note`).
Целостность проверяет `tests/calc-extended.test.mjs` (у каждого значения есть источник, дата и надёжность;
`null` допустим только вместе с `no_data`).

**Юр-пометка во всех налоговых данных:** «Проверено: дата · Источник · Требует консультации со специалистом».
Сайт — справочный инструмент для одного человека, а не налоговая консультация.

## Статусы

| Статус | Значение |
|---|---|
| подключён | данные обновляются скриптом/cron без участия человека |
| ручной | значение внесено человеком по первоисточнику, указана дата проверки |
| вторичный | подтверждено справочными системами/СМИ, первоисточник не открыт |
| предположение проекта | `confidence:"model"`, редактируется в интерфейсе, к источникам не относится |
| нужен токен | источник существует, но требует ключа владельца |

## 4. Автоматическое обновление

- `scripts/fetch-cbr.mjs` — курсы из ЦБ (без ключей). При недоступности прежние значения сохраняются и помечаются `stale:true`.
- `scripts/fetch-news.mjs` — новости отрасли из RSS (раздел 4а), ежедневно; копит записи 60 дней, не больше 40.
- Workflow `.github/workflows/data-refresh.yml` — ежедневно, cron 03:17 UTC и страховочный 15:47 UTC (GitHub запускает расписание
  с задержкой до нескольких часов и иногда пропускает) + `workflow_dispatch`; коммитит изменения в `data/` и явно запускает
  `deploy.yml` (`gh workflow run`, права `actions: write`): пуш от `GITHUB_TOKEN` сам другие workflow не запускает.
  Если по существу ничего не изменилось, но ЦБ ответил, раз в 2 дня ставится `meta.checked_at` («источники проверены») —
  чтобы в долгие праздники без новых курсов данные не считались устаревшими.
- `scripts/fetch-leads.mjs` и `scripts/fetch-competitors.mjs` — «потенциальные клиенты» (4б) и проверка сайтов конкурентов (4в), раз в неделю; workflow `.github/workflows/weekly-refresh.yml` (понедельник 02:30 UTC + `workflow_dispatch`), коммит от `data-bot`, затем запуск деплоя.
  Места, где Overpass не дал слот (502/504), опрашиваются вторым кругом через минуту.
- Аудит свежести — `scripts/data-freshness.mjs` (вызывается из `touch-meta.mjs` в обоих workflow, вручную — `node scripts/data-freshness.mjs`):
  печатает `::warning` в сводке прогона, если курсы ЦБ старше порога или помечены stale, лента новостей молчит дольше 7 дней
  (`news.sources[].last_ok_at`), «клиенты» старше 10 дней, автопроверка конкурентов старше 14, окна грантов сверялись больше 30 дней
  назад или грант «открыт» после последней даты окна, нет значения налога на текущий год (с декабря — напоминание о следующем),
  не загружен календарь каникул. Пороги — `meta.refresh_policy.stale_after_days` и `rates.thresholds_days`.
- Пороги устаревания (бейдж «устарело»): ставки — 7 дней, цены — 30, гранты — 30 (`rates.thresholds_days`, `config.ui`);
  новости — 14, клиенты — 10, проверка конкурентов — 14 (`meta.refresh_policy.stale_after_days`).
- **Ограничение GitHub Actions (проверено по логам 21.11.2026):** серверы GitHub находятся за рубежом, и сайты `mk.nso.ru`, `nso.ru`
  (HTTP 502) и `culture.gov.ru` (таймаут) им не отвечают — из ежедневного прогона реально обновляются только курсы ЦБ и лента ФНС.
  Прежние записи при этом сохраняются, в `news.json` видно `sources_failed` и у каждой ленты `last_ok_at`. Из российской сети те же
  ленты открываются (локальный прогон 21.11.2026: 5 из 5). Обновить с компьютера владельца: `node scripts/refresh-local.mjs`
  (ежедневные источники) или `node scripts/refresh-local.mjs --weekly` (плюс клиенты и конкуренты), затем
  `git add data/ && git commit && git push` — пуш владельца сам запускает деплой. Постоянное решение — self-hosted runner в РФ
  (решение владельца).
- Кнопка «Обновить данные» на сайте (`js/live-data.js`) перечитывает все `data/*.json` мимо кэшей (`?t=…`, `cache:'reload'`),
  называет, что пришло нового, и перезагружает страницу; если нового нет — пишет «Данные актуальны · проверены …».
  Курс ЦБ напрямую из браузера не запрашивается (cbr.ru не разрешает CORS).

## 4а. Новости отрасли (`data/news.json`, `scripts/fetch-news.mjs`)

Ежедневно (тот же cron `data-refresh.yml`) скрипт качает публичные RSS-ленты, оставляет только записи
по ключевым словам ленты, нормализует (`id` — sha1 канонической ссылки, `title`, `summary` ≤ 200 знаков без HTML, `url`,
`source_name`, `source_url`, `published_at` ISO UTC, `topic`: `grants | taxes | culture | city | industry`),
удаляет дубли (одна ссылка или похожий заголовок) и **копит** записи: последние 60 дней, не больше 40, новые сверху.
Ленты отдают по 5–40 последних записей, поэтому история собирается со временем. Ничего не выдумывается:
нет совпадений — у ленты `status:"empty"`; лента не ответила — `status:"error"` и текст ошибки; все ленты упали —
прежние записи остаются, `stale:true`, `stale_since`. Если по существу ничего не поменялось, файл не переписывается
(нет пустых коммитов бота). robots.txt проверяется и при каждом запуске (путь запрещён — лента пропускается со статусом `error`).
В интерфейсе (`js/news.js`) показываются записи не старше 14 дней; при `stale` старше 14 дней — ничего.

- **Google News RSS** (`news.google.com/rss/search?…`) — в robots.txt для `User-agent: *` стоит `Disallow: /`, а `/rss` не разрешён (разрешены только `/topics/`, `/stories/` и т. п.). Не используем.

- **Минкультуры России, корень `/rss/`** — пустой ответ; рабочие ленты перечислены на `https://culture.gov.ru/rssall/`.
- **culture.nso.ru, mincult.nso.ru, mineconom.nso.ru** — хосты не ответили (нет соединения); актуальный сайт министерства культуры НСО — `mk.nso.ru` (подключён).

Как добавить ленту: дописать объект в `SOURCES` (`scripts/fetch-news.mjs`) с `feed_url`, `topic`, `filter`, проверить robots.txt хоста,
прогнать `DATA_DIR=<копия data> node scripts/fetch-news.mjs` и посмотреть, сколько записей проходит фильтр (цель — без шума).

## 4б. Потенциальные клиенты (`data/leads.json`, `scripts/fetch-leads.mjs`)

Блок «Потенциальные клиенты» в «Навигаторе рынка»: сколько школ, детских садов и ДК/клубов в Новосибирске (по районам) и в
Бердске, Искитиме, Коченёве, Мошкове, Ордынском. **Потенциал на выезд = школы + детские сады** (учреждения, куда можно
предложить выездной показ); ДК и клубы считаются отдельно как площадки. Никаких коэффициентов спроса в расчёте нет.

| Параметр | Значение |
|---|---|
| Источник | OpenStreetMap через Overpass API, зеркало VK Карт (`maps.mail.ru/osm/tools/overpass`); `overpass-api.de` по умолчанию не используется (см. robots.txt ниже), его можно включить переменной `OVERPASS_ENDPOINTS` |
| Теги | `amenity=school`, `amenity=kindergarten`, `amenity=community_centre`, `amenity=arts_centre` |
| Лицензия | ODbL 1.0, © участники OpenStreetMap ([openstreetmap.org/copyright](https://www.openstreetmap.org/copyright)); атрибуция выводится в блоке |
| Ключи | не нужны |
| График | раз в неделю, понедельник 02:30 UTC — `.github/workflows/weekly-refresh.yml` (+ ручной запуск) |
| Охват | 6 населённых пунктов; Новосибирск — 10 районов; границы заданы id отношений OSM (найдены через Nominatim 21.11.2026: Новосибирск 1751445, Бердск 1307315, Искитим 3396079, Коченёво 7606008, Мошково 7613336, Ордынское 7613465) |
| Статус | подключён; первый прогон 21.11.2026 (результат — в `data/leads.json`) |
| Ограничения | OSM неполон: часть учреждений не нанесена, часть без названия; одно здание может быть нанесено точкой и контуром (скрипт убирает такие дубли: то же имя и расстояние меньше 300 м). Числа — **оценка снизу**, не реестр. В интерфейсе стоит пометка «По данным OpenStreetMap, возможны пропуски» |
| Сбои | Overpass часто отвечает 502/504 (очередь слотов): скрипт ждёт 12 и 30 с, пробует зеркало, общий бюджет 30 мин. Сбой места не затирает прежние числа — место получает `stale:true` и `stale_reason`; сбой всех мест ставит `stale:true` для всего файла и не двигает `updated_at`. Подозрительно пустой ответ (нет объектов или меньше половины прежнего) отбрасывается. Старше 10 дней — бейдж «Данные устарели» |
| Ручные правки | Юлия может поправить числа места в блоке («Скорректировать вручную»); значения хранятся в `localStorage` браузера, помечены «вручную» и не меняют `data/leads.json` |

**robots.txt и условия (проверено 21.11.2026).** У `overpass-api.de` в robots.txt стоит `Disallow: /api/` для всех агентов.
Это правило направлено на индексацию поисковиками; сам Overpass API создан для запросов из программ и допускает их по своей
политике использования (до 10 000 запросов и 1 ГБ в сутки, с оглядкой на нагрузку). Мы делаем около 6 запросов в неделю,
последовательно, с паузой 3 с и `User-Agent` проекта без личных данных. Поэтому по умолчанию в `ENDPOINTS` оставлено только зеркало VK Карт (решение принято по замечанию приёмки); основной сервер можно вернуть переменной `OVERPASS_ENDPOINTS`, если владелец сочтёт это допустимым. Прежнее допущение: запросы к основному серверу (у `maps.mail.ru` robots.txt ограничений для API не задаёт,
но зеркало чаще отвечает 504). Клиентский таймаут запроса — 60 с вместо общих 10 с: Overpass считает запрос на сервере,
ответ приходит за 20–40 с (исключение зафиксировано в шапке скрипта). Nominatim использовался один раз вручную для поиска
id границ и в скрипт не входит (его robots.txt закрывает `/search`).

**Что проверено и не подошло (21.11.2026, честный список):**

| Кандидат | Результат |
|---|---|
| Рособрнадзор, реестр организаций | открытого машиночитаемого API без ручной выгрузки не найдено — не подключён |
| data.nso.ru (открытые данные НСО) | хост не ответил за 10 с (таймаут соединения) — не подключён |

## 4в. Конкуренты — недельная проверка (`data/competitors.json`, `scripts/fetch-competitors.mjs`)

Раз в неделю для каждой записи с публичной страницей-источником скрипт: проверяет `robots.txt` хоста (запрещено — пропуск,
`check_status:"robots_disallowed"`), скачивает страницу (таймаут 10 с, повторы 500 мс × 2ⁿ), считает **устойчивый хеш видимого
текста** (регистр, ё/е и пробелы не влияют) и сравнивает с прошлой неделей. Пауза 2,5 с между запросами к одному хосту, единый
`User-Agent` проекта, без обхода защиты, капчи и авторизации.

| Поле записи | Смысл |
|---|---|
| `check_status` | `ok` (доступна, не изменилась или первая проверка), `changed` (текст изменился), `unavailable` (сеть/HTTP/robots.txt недоступны; прежние наблюдения сохраняются), `robots_disallowed`, `skipped_policy` (2ГИС, VK, Яндекс, Zoon и т. п. — их условия запрещают автоматический сбор, запросов нет), `skipped` (ссылки нет или она не http/https) |
| `checked_at` | дата и время последней проверки (UTC) |
| `observed.content_hash`, `hash_at`, `changed_at`, `last_ok_at` | хеш текста, когда этот хеш впервые увиден, когда текст менялся в последний раз, когда страница последний раз открылась |
| `observed.price` | **только если** на странице явно и однозначно найден ценник (число + «₽ / руб. / р.») в пределах 80 знаков от слов «билет, спектакль, программа, стоимость, цена, вход, сеанс, шоу, занятие, выезд…». `confidence:"low"` (авто-извлечение), со ссылкой и датой. Телефоны, ИНН/ОГРН, суммы вне 50–300 000 ₽ и числа без валюты — не цена; несколько разных цен или диапазон — цена не записывается (`price_note`) |
| `observed.prev_price` | цена прошлой недели, если на сайте она поменялась |

**Ручные значения `prices[]` не меняются никогда.** В карточке рядом с ценой показывается «на сайте: от 300 ₽ · проверено дата»;
если цены сайта нет среди цен карточки или она изменилась за неделю — пометка «цена на сайте изменилась». Без найденной цены
выводится только «страница доступна / изменилась / недоступна».

| Параметр | Значение |
|---|---|
| График | раз в неделю вместе с «Потенциальными клиентами» (`weekly-refresh.yml`) |
| Охват (21.11.2026) | 12 записей со ссылкой: 6 проверяются (`nsk.nik-show.ru`, `nsk-warstation.ru`, `unc-planetary.ru`, `sovenok.edusite.ru`, `ds428nsk.edusite.ru`, `playpanda.ru`), 6 пропущены по политике площадок (2ГИС, VK, Яндекс Афиша, Zoon) |
| robots.txt | проверяется перед каждым хостом при каждом запуске; результат кэшируется на прогон |
| Ограничения | динамические блоки страницы (счётчики, даты) могут давать ложное «страница изменилась»; цена извлекается регулярным выражением, поэтому всегда «низкая» надёжность и требует ручной сверки |

### Каникулы

Машиночитаемого официального источника дат каникул НСО нет, поэтому `seasonality.json → school_holidays` ведётся вручную.
Без дат следующего года «Сегодня → Ближайшее» после окончания зимних каникул теряет каникулы, а раздел «Каникулы» пишет
«даты ещё не загружены» (ничего не придумывается). Ежедневный workflow печатает `::warning` в сводке прогона, если
не загружен текущий год или до конца года меньше 60 дней, а следующий год не загружен (`scripts/touch-meta.mjs`).

Как внести год: найти приказ/график на [do.nios.ru](https://do.nios.ru) или сайте Минобразования НСО и заменить
`"<год>": { "loaded": false, ... }` на `{ "loaded": true, "checked_at": "ГГГГ-ММ-ДД", "source_name": ..., "source_url": ...,
"confidence": "medium", "items": [{ "name": "Осенние", "from": "ГГГГ-ММ-ДД", "to": "ГГГГ-ММ-ДД", "verified": true }] }`.
Названия — те же, что в `market.json → school_calendar.holidays` (сопоставление идёт по первому слову: «Осенние», «Зимние»,
«Весенние», «Летние»). Если даты — ориентир, а не приказ, ставить `"verified": false` и `"confidence": "low"`.

## 6. Как получить токен Wordstat

1. Кабинет Яндекс OAuth → зарегистрировать приложение с правами на API статистики (scope — по актуальной документации Яндекса, не угадывать).
2. Получить OAuth-токен, добавить в GitHub Secrets как `WORDSTAT_TOKEN`.
3. Доработать `scripts/fetch-wordstat.mjs` (каркас описан в файле): запрос по `market.demand.queries`, регион Новосибирская обл.
4. Результат писать в `market.demand` со `status:"ok"` и полным провенансом.
